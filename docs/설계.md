# Thought Drawer 설계

## 목표

메모, 캡처, 웹사이트 북마크, 인스타 저장 게시물을 한곳에 던져 넣으면 Claude가 폴더별로 정리하고 서로 이어 주고,
나중에 검색하거나 문장으로 물어서 다시 찾는다. 폰과 PC에서 같은 내용을 본다.

**제약**: 추가 비용 0원. 유료 API, 유료 서버를 쓰지 않는다. AI는 이미 쓰는 Claude 구독으로만 돌린다.
구독 사용량도 아낀다.

## 구조

```
[아이폰 / PC]  웹앱 (GitHub Pages, 서버 없음)
   │  구글 로그인 (drive.file: 앱이 만든 파일만)
   ▼
[구글 드라이브 「메모」]  유일한 저장소, 마크다운 + 사진
   ▲
   │  하루 2~3번
[Claude Code 예약 작업]  organizer/ (구독으로 실행)
```

| 부분 | 하는 일 | AI 사용 |
|---|---|---|
| 웹앱 `js/` | 노트 넣기와 쓰기, 찾기, 묻기, 연결과 그래프, 인스타 일괄 가져오기, 내보내기 | 없음 |
| 정리기 `organizer/organize.py prepare` | 인박스 노트 모으기, 링크·인스타 캡션 가져오기, 연결 후보 고르기 | 없음 |
| Claude (예약 작업) | `batch.md`를 읽고 제목·폴더·태그·요약·연결을 `decisions.json`으로 결정 | **여기서만** |
| 정리기 `apply` | 노트 고치기, 폴더로 옮기기, 거꾸로 연결, 색인 만들기 | 없음 |
| 묻기 → "Claude에게 묻기" | 관련 노트 요약을 붙여 claude.ai 새 대화를 연다 | 사용자의 구독 채팅 |

## 노트 형식 (제텔카스텐)

노트 하나 = 마크다운 파일 하나. 옵시디언이 그대로 읽는다.

## 사진 속 글자

- 넣을 때는 사진만 줄여 올리고 바로 노트를 만든다(드라이브 글자 인식을 기다리지 않아 폰 공유가 빠르다). 글자가 없으니 우선 「생각·기록 › 캡처」(weak)에 둔다.
- Claude 정리기: 글자가 거의 없는 사진 노트는 640px로 줄인 사진을 Claude가 직접 본다. Claude는 사진 속 이름·글자로 무엇인지 알아내 제목·서랍·태그·요약을 정하고, `photo_text`에 **중요한 글자만**(상품명·브랜드·가격, 가게·장소·주소, 전화, 행사·예약 날짜, 핵심 문장. 120자 이내) 적는다. 시계·배터리·통신사, 메뉴·버튼, 좋아요 수, 광고 문구 같은 화면 글자는 넣지 않는다. `apply`가 이것으로 「## 사진 속 글자」를 바꿔 쓴다.
- 크롬 확장의 화면 캡처는 지금처럼 드라이브 글자 인식으로 글자를 함께 적는다.
- 드라이브 저장소는 「메모」 폴더를 한 번만 찾아 두고, 동기화보다 저장이 먼저 시작돼도(공유로 막 열었을 때) 그 폴더를 찾은 뒤에 쓴다.

## 사용량 아끼기

- 한 번 정리한 노트는 다시 보내지 않는다: Claude가 정리하면 머리말에 `organized` 시각이 남고, `prepare`는 인박스에 있어도 이 표시가 있는 노트는 뺀다. 다시 맡기려면 앱의 노트 메뉴 「Claude에게 다시 맡기기」(표시를 지우고 인박스로).
- 새 노트가 없으면 Claude가 아무것도 읽지 않고 끝난다.
- 한 번에 최대 30개, 약 14,000자. 남은 건 다음 정리로 넘긴다(최근 것부터).
- 링크 내용, 캡션, 사진 글자는 스크립트가 미리 줄여서 넣는다. 앱이 자동으로 쓴 안내 문장은 뺀다.
- 연결 후보는 낱말이 겹치는 노트 4개만 보여 준다. 전체 목록을 주지 않는다.
- 사진은 글자가 거의 없을 때만 640px로 줄여 보여 준다.
- 권장 모델은 Haiku.

## 구글 연결 이어 가기

`js/store/auth.js` · `js/ui/App.js`

- 서버가 없어서 구글이 주는 열쇠(access token)는 1시간짜리이고, 오래가는 열쇠(refresh token)는 받을 수 없다(받으려면 보안 비밀을 숨길 서버가 필요).
- 그래서 저절로 다시 받는다. 앱을 열 때 만료됐으면 구글로 잠깐 이동(`prompt=none`, `login_hint`)해서 화면 없이 새 열쇠를 받고 보던 화면(`#/...`)으로 돌아온다. 구글 로그인이 풀려 거절되면 10분 동안은 다시 시도하지 않고 「다시 연결」 띠를 보여 준다(되풀이 없음). 인터넷이 없으면 다녀오지 않는다.
- 쓰는 중에는 끝나기 5분 전부터 구글 로그인 스크립트를 미리 받아 두고, 다음 클릭 때 작은 창으로 새로 받는다(이미 허용했으면 누를 것 없이 닫힘). 드라이브 요청은 새로 받는 동안 기다렸다가 보낸다. 아이폰 홈 화면 앱은 창 대신, 앱으로 돌아올 때(적던 글이 없으면) 구글에 잠깐 다녀온다.
- 자동 정리기용 열쇠(refresh token)는 따로 받아 Claude Code 환경에 둔다. 구글 클라우드 동의 화면이 「테스트」면 7일 뒤 끊기니 「프로덕션」으로 둔다(drive.file은 민감하지 않은 권한이라 심사 없이 됨).

## 화면 디자인

애플 홈페이지의 말과 짜임, 맥의 폴더 보기, 옵시디언의 작업 공간을 섞었다. 기능은 네 가지 기준(쉽게 넣기, 어느 기기에서나, 무엇이든 담기, 자동 분류)을 그대로 따른다.

- 위 막대: 52px, 반투명. 왼쪽 ☰(옆 메뉴)와 서랍이·이름, 오른쪽 찾기(빠른 실행)와 내 계정. 넣기 단추는 따로 두지 않는다(첫 화면의 넣는 칸, Enter, 옆 메뉴의 「넣기」).
- 내 계정(오른쪽 위 사진): 구글 계정에 관한 것만, 말은 짧게. 이름·이메일, 연결 상태(끊겼으면 「다시 연결」), 저장 공간 막대(드라이브 API `about.storageQuota`: 전체 · 쓴 양 · 드라이브 / 「메모」 폴더 크기는 파일 목록의 크기 합. 메모 · 드라이브 · Gmail·포토 · 남음, 90% 넘으면 경고), 메모 폴더 열기, 동기화, 구글 계정, 로그아웃(묻고 나서). 넣기·오늘 노트·설정 같은 메뉴는 왼쪽 옆 메뉴에만 둔다.
- 옆 메뉴: ☰로 열면 옆에서 미끄러져 나오고(바깥을 누르거나 Esc로 닫힘), 핀을 누르면 넓은 화면에서 왼쪽이나 오른쪽에 고정된다(⇄로 옮김, 이 기기에 기억). 넣기, 홈, 모든 서랍, 모든 노트·필터, 할 일(남은 수), 오늘 노트, 생각 지도, 즐겨찾기, 서랍 목록(색 점과 수), 아래쪽에 설정, 사용법. 가져오기는 넣는 칸의 + 에만(옆 메뉴에 또 두면 헷갈려서). 찾기 칸은 두지 않는다(위 막대의 돋보기).
- 첫 화면
  - 첫 화면 높이 가득, 가운데에 큰 제목 「넣기만 하세요. 정리는 서랍이.」, 한 줄 부제 「무엇이든 넣으면 알아서 분류해드립니다.」, 넣는 칸만 둔다(노트는 보이지 않게). 적는 동안 어느 서랍으로 갈지 칸 아래 칩으로. 맨 아래 「내 서랍」.
  - 넣는 칸 왼쪽 +: 사진·스크린샷, 붙여넣기(복사한 링크·글·사진), 북마크 가져오기, 인스타 가져오기, 다른 앱에서 넣기를 목록으로 연다. 넣는 방법은 칸 밖에 늘어놓지 않고 여기에만 둔다.
  - 화면 글은 짧게(이름은 명사, 설명은 한 문장). 서랍이 말풍선만 말하듯.
  - 서랍이: 넣는 칸 위 왼쪽에 앉아 있다(아래쪽은 칸에 가려 고개만 내민 모양). 들어오면 시간에 맞춰 인사, 적으면 글 쪽을 보고 「링크네요! 쇼핑 서랍에 넣을게요」 「요리 서랍이 어울려요」, 넣으면 웃으며 뛰고 「좋아요, 요리 서랍에 넣어 둘게요」, 사진을 끌어 오면 놀라며 「여기 놓으세요!」, 30초 넘게 가만히 있으면 쓰는 법을 하나씩(세 번까지), 누르면 말을 걸고 뛴다. 가끔 눈을 깜빡인다. 다른 곳의 말(`say()`)도 이 말풍선으로 받는다.
  - 아래로 내리면 「내 서랍」 제목과 오늘 줄(날짜, 남은 할 일, 오늘 노트), 그 아래 서랍 폴더만(맥의 폴더 보기처럼 파란 폴더 아이콘 + 이름 + 개수, 맨 끝에 모든 노트·즐겨찾기). 노트 카드는 첫 화면에 두지 않는다(누르면 서랍 화면에서 본다).
  - 서랍이 동행(`js/ui/parts/buddy.js`): 모든 화면 오른쪽 아래. 화면마다 한 번 한마디(서랍 화면은 서랍 이름과 노트 수, 할 일은 남은 수…), `say()`로 오는 말(넣었어요 등)을 받고, 누르면 메뉴. 첫 화면 넣는 칸이 보이는 동안·폰에서 노트 쓰는 동안은 숨는다. 「서랍이 동행」(보이기), 「서랍이 말」(자주/가끔/끔) 설정을 따른다.
  - 바닥: 「© 연도 makerskim. All rights reserved.」 한 줄만. 개인정보처리방침·약관은 로그인 화면과 설정 → 도움말에 있다(구글 로그인 심사용 링크는 로그인 화면이 맡는다).
- 서랍이는 그 밖에: 넣었다는 알림 앞, 노트의 자동 분류 이유(「서랍이가 coupang.com 링크라서 쇼핑 서랍에 넣었어요」), 옆 메뉴 머리(열 때 손 흔듦), 빈 화면, 사용법 안내.
- 서랍 모음: 「서랍.」 큰 제목 아래 서랍마다 타일(서랍 색 아이콘, 노트 수, 자동 분류 수, 세부 서랍별 수, 최근 노트 세 개).
- 서랍 하나·태그·즐겨찾기·찾기: 두 번째 막대(애플 제품 페이지의 로컬 막대: 뒤로, 이름, 보기 메뉴), 「쇼핑.」 큰 제목과 노트 수(걸렀으면 「N개 / 전체 N개」), 자동 분류 안내, 세부 서랍 칩, 필터 막대, 카드 판(또는 목록에서 여러 개 골라 옮기기·지우기). 세부 서랍을 열면 그 아래 소분류 칩 줄이 하나 더 나온다(쇼핑 › 가전 → 휴대폰 · 청소기 …). 카드 바닥에 「서랍 › 세부 서랍 › 소분류」.
- 설정: 아이폰 설정처럼 묶음(회색 제목 + 오른쪽에 「이 기기」「모든 기기」 표시 + 둥근 흰 판)마다 짧은 이름 한 줄씩(8자 안, 설명은 꼭 필요할 때만 12자 안). 화면 · 입력 · 자동 분류(맨 위 「해 보기」) · 분류 규칙 · 내 명령어(기본 /할일 /오늘 /내일 /어제 /지금 포함, 바꿀 수 없는 동작은 맨 아래 한 줄) · 데이터 · Claude 자동 정리(상태 + 접힌 「켜는 법」 3단계). 계정은 오른쪽 위 사진, 단축키·기본 동작·도움말은 사용법에. 규칙·명령어 창: 「이 낱말·사이트가 나오면 / 넣을 서랍 / 달 태그」, 「이름 / 넣을 글 + 끼워 넣기 단추 + 미리 보기」. 어두운 화면에서는 고르기 목록의 펼친 줄도 어두운 종이색.
- 사용법(`#/help`): 13장(시작하기, 넣기, 가져오기, 자동 분류, / 명령어, # 태그·@ 서랍, 찾기와 필터, 노트 쓰기, 할 일·오늘 노트, 계정과 설정, 단축키, 자주 묻는 질문, 도움말). 넓으면 왼쪽에 붙어 있는 목차, 폰은 위쪽 칩. 화면 안내 다시 보기 단추.
- 노트(옵시디언 작업 공간): 세 칸. 왼쪽은 같은 서랍의 노트 목록(지금 노트 표시), 가운데는 위 막대(닫기, 이전·다음, 서랍 › 제목, 저장 상태, 즐겨찾기, 더 보기)와 큰 제목, 속성 표(서랍과 자동 분류 이유, 태그, 종류, 출처, 만든 날), Claude 요약 콜아웃, 내 생각, 템플릿, 편집기. 오른쪽은 연결(이어진 · 언급한 · 비슷한 노트) · 목차 · 로컬 그래프 탭. 좁은 화면에서는 왼쪽부터 접고, 폰은 한 칸으로 아래에 이어 붙인다. `J`/`K`는 보던 목록(없으면 같은 서랍) 순서로 넘긴다. `Esc`는 보던 화면으로.
- 한 글자 단축키(`js/ui/keys.js` 한 표): H 홈, D 모든 서랍, A 모든 노트·필터, C 할 일, T 오늘 노트, G 생각 지도, F 즐겨찾기, N 새 노트, `,` 설정, `?` 사용법. 옆 메뉴 이름 오른쪽 글자와 빠른 실행 목록에 같은 글자를 보여 주고, 자판 위치(`e.code`)로 받아서 한글 입력 상태(ㅗ·ㅇ…)에서도 된다. 입력칸에 쓰는 중에는 받지 않고, 옆 메뉴가 떠 있어도 받는다(가면 메뉴는 닫힘). 자판 없는 폰에서는 글자를 숨긴다.
- 빠른 실행(애플 검색 + 옵시디언 명령 팔레트): `/` 또는 `Ctrl/⌘ K`. 적는 대로 노트를 찾고, 할 일 이름(오늘 노트, 설정, 북마크 가져오기…)과 맞으면 그 명령을 먼저 보여 준다. 「모두 찾아보기」와 「Claude에게 물어보기」.
- 색과 글: [디자인시스템.md](디자인시스템.md)의 규칙을 따른다. 중립 회색 + 애플 파랑 하나, 카드는 모두 같은 종이, 서랍은 작은 색 점으로만. 밝기 「자동」은 해 뜨고 지는 시각(`js/core/sun.js`, 기기 시간대로 경도 어림, 한국 시간대면 서울)에 맞춰 바뀌고 1분마다·앱으로 돌아올 때 다시 본다. 「기기」는 기기 설정 따라, 밝게·어둡게는 고정. 브라우저 위 막대 색도 같이 바꾸고, 그리기 전 깜빡임이 없게 index.html 머리에서 먼저 어림으로 정한다. 글꼴은 Pretendard.

## 자동 분류

`js/core/classify.js` (기기 안에서, 넣는 즉시. 서버·AI 요청 없음)

- 대분류(서랍)를 먼저 고르고, 그 안에서 같은 방법으로 중분류(세부 서랍)를, 마지막에 소분류를 고른다. 「기타」는 없다.
  - 서랍: 아래 점수의 합이 0.5점 이상인 가장 높은 서랍. 점수가 같으면 사전 순서(쇼핑 … 생각·기록)가 앞선 쪽.
  - 세부 서랍: 같은 점수 방식으로 고르고, 같으면 글에 먼저 나온 쪽. 모자라면 그 서랍의 기본 세부 서랍(쇼핑 → 위시리스트, 생각·기록 → 메모 …).
  - 소분류: 그 세부 서랍 낱말 중 글에 먼저 나온 것(묶음이 있으면 묶음 이름: 아이폰·갤럭시 → 휴대폰) → 다른 서랍의 낱말 → 전화번호 같은 신호 → 사이트 이름 → 제목·첫 줄의 첫 이름 같은 낱말. 서랍·세부 서랍 이름과 같은 말은 쓰지 않는다.
  - 단서가 하나도 없으면: 모르는 사이트는 주소로 짐작(shop → 쇼핑, news → 뉴스·이슈, blog → 공부·자료 › 아티클, 그 밖 → 아티클), 글자 없는 사진은 생각·기록 › 캡처, 나머지는 생각·기록 › 메모(첫 낱말이 소분류). 이렇게 둔 노트는 weak 로 표시해 연관 노트 점수에서 「같은 서랍」을 더하지 않는다.
  1. 내 분류 규칙(설정): 낱말이나 사이트가 나오면 10점, 정한 세부 서랍과 태그를 그대로 쓴다.
  2. 사이트: 서랍·세부 서랍마다 알려진 주소(쿠팡 → 쇼핑, 다나와 → 쇼핑 › 가전, 아고다 → 여행 › 숙소…). 맞으면 4점. 링크 노트가 아니어도 글 속 첫 주소를 본다.
  3. 낱말: 서랍·세부 서랍마다 낱말 목록. 맞은 낱말 하나에 1.2점(+ 표시 3점, 사이트 이름 4점, 흔한 말 0.8점), 서랍마다 6점까지. 영어는 낱말 단위(ai가 mail에 걸리지 않게), 한 글자 한글(책·쌀·찜)은 다른 낱말 속(책임·책상)에 걸리지 않게 앞뒤를 본다.
  - 낱말은 글을 한 번 훑어 긴 낱말이 먼저 자리를 차지한다(「운동화」 속 「운동」, 「카페인」 속 「카페」, 「시계열」 속 「시계」는 세지 않음). 「주식회사」「고기압」「회의적」「토스트」 같은 함정 말은 막아 둔다.
  - 무게: 보통 1.2, 흔한 말(주문, 쿠폰, 세일, 생각, 기록) 0.8, 글의 성격을 정하는 말(아이디어, 일기, 회고, 명언, KTX) 3, 사이트의 한국어 이름(무신사, 배민, 디즈니플러스 — 뜻이 여럿인 멜론·크림 등은 뺌) 4.
  - 점검: 실제로 적을 법한 글 100여 개로 맞는지 보고, 그중 24개는 `tests/features.test.js`에 넣어 늘 확인한다.
  4. 글 모양: 전화번호·메일 → 사람·연락 › 연락처, 체크 목록 → 할 일·일정 › 할 일(늘 셈). 시각·날짜 → 일정, 금액 → 가계부, 물음표 → 질문, 「~하기」 → 할 일은 내용으로 1.2점이 안 될 때만 센다(「치과 예약 내일 3시」는 병원, 「내일 3시」만 있으면 일정).
  5. 배운 것: 내가(또는 Claude가) 서랍을 정한 노트에서 서랍·세부 서랍마다 자주 나오는 낱말과 사이트를 세어 두고 비교한다. 노트가 적은 서랍은 덜 믿는다.

### 자동 분류 점검 (대량)

- `node tools/classify-bench.mjs <말뭉치 폴더> [--mine 300] [--json 결과.json]`: 공개 한국어 말뭉치를 넣어 기타 수, 단서 없이 메모로 간 비율, 소분류가 없는 비율, 출처별로 기대한 서랍에 간 비율, 메모로 간 글에 자주 나온 모르는 낱말을 센다. 말뭉치는 저장소에 넣지 않는다(용량·저작권).
- 쓴 말뭉치(raw.githubusercontent.com 에서 받음): 네이버 영화 리뷰 NSMC(e9t/nsmc, 20만), 네이버 쇼핑 리뷰·스팀 게임 리뷰(bab2min/corpus, 20만·10만), 챗봇 일상 대화(songys/Chatbot_data), 3i4k 말 의도(warnikchow/3i4k), 고민 질문 쌍(songys/Question_pair), 연예 댓글(kocohub/korean-hate-speech), 댓글 Unsmile(smilegate-ai/korean_unsmile_dataset), KorNLI 여러 글(kakaobrain/kor-nlu-datasets), KLUE 뉴스 제목 YNAT(KLUE-benchmark/KLUE, 주제 정답 있음), KoAlpaca 질문(Beomi/KoAlpaca). 모두 합쳐 85만 7천 줄.
- 결과(2026-11): 기타 0개 · 세부 서랍 없음 0개 · 단서 없이 메모 36.3% → 14.1% · 소분류 없음 7.0% → 3.4% · 기대한 서랍: 쇼핑 리뷰 51% → 67%, 게임 리뷰 26% → 44%, 영화 리뷰 31% → 41%, 뉴스 제목(주제 정답 대비) 39% → 62% · 글 하나 0.075ms. 남은 「메모」는 대부분 주제어 없이 「너무 좋아요」「그냥 그래」처럼 기능어만 있는 글이고, 리뷰 중 주제어 없이 평만 적은 글은 생각·기록 › 감상(좋음·별로)으로 간다.
- 과정: ① 출처마다 유난히 자주 나오는 낱말을 log-odds 로 뽑아 사람이 검토해 세부 서랍에 넣고 ② 뜻이 둘인 말(기타=악기/그 밖, 사기=속임/사다, 이란=나라/~이란, 바람=바람피움/바람)과 한 글자 말(새·말·산·달)은 빼거나 약하게 하고 ③ 다른 말 속에 걸리는 낱말을 찾아 첫머리에서만 찾게 하고 ④ 기존 점검 104개와 235개 예문이 그대로 맞는지 매번 확인했다.
- 빠르기: 낱말을 앞 두 글자로 묶어 글에 있는 두 글자만 찾아보고(scan), 찾은 낱말에서 거꾸로 서랍을 본다(WHERE). 노트 하나에 0.1ms 남짓.
- 폴더와 규칙도 세 단계까지(「쇼핑/가전/노트북」). 옮겨 둔 폴더가 두 단계면, 자동 분류가 같은 서랍을 골랐을 때 그 소분류를 화면에서만 붙인다.
- 자동 태그(기본 4개, 설정에서 0~8): 규칙의 태그 → 이미 쓰는 태그 중 글에 나온 것 → 사이트 이름(#쿠팡) → 세부 서랍 낱말 → 서랍 낱말 → 다른 서랍 낱말. 낱말 조각(「사고 싶」)은 태그로 쓰지 않고, 「항공권」이 있으면 「항공」은 뺀다. 새 노트는 넣을 때 태그를 파일에 써 두고(옵시디언에서도 보임), 태그가 없는 예전 노트는 화면에서만 자동 태그로 보인다(노트에서 「태그로 저장」).
- 파일은 옮기지 않는다. 서랍이 정해지지 않은 노트(인박스)는 화면에서만 자동 서랍에 보이고, 노트에서 서랍을 고르거나 `@서랍`으로 넣으면 그때 그 폴더로 옮긴다(이후 학습 자료가 된다). 그래서 드라이브가 잠깐 안 돼도 분류는 늘 보이고, 선택으로 켜는 Claude 정리기와도 부딪히지 않는다(정리기는 인박스 노트를 다듬어 폴더로 옮기고, 내 분류 규칙을 batch.md에 받아 그대로 따른다).
- 북마크 가져오기는 북마크 폴더 이름(의미 없는 「북마크바」 등은 뺌)을 태그로 붙이고, 원래 저장한 날짜를 쓴다.

## 서랍 이름 바꿈 장부

서랍 이름이나 분류 설정이 바뀌어도 이미 정리된 노트를 다시 분류하지 않는다. 이름만 옮긴다.

- 장부: `[{ from: '옛 경로', to: '새 경로', at }]`. 내가 바꾼 것은 `_시스템/settings.json`의 `renames`, 앱이 바꾼 기본 이름은 `js/core/taxonomy.js`의 `RENAMED`(→ `organizer/taxonomy.json`의 `renamed`). 둘을 합쳐 쓰고 내 것이 이긴다.
- 규칙(`js/core/renames.js` ↔ `organizer/td_note.py`, `tests/fixtures/renames.json`으로 둘 다 확인): 경로 앞부분이 옛 이름과 같으면 새 이름으로(「쇼핑」은 「쇼핑몰」에 걸리지 않음). 긴 옛 이름이 먼저. A→B 뒤 B→C 는 A→C 로 접고, A→B 뒤 B→A 는 지워서 돌고 도는 바꿈이 생기지 않는다. 옮길 곳이 다시 바뀌는 이름이면 옮기지 않는다(파일이 왔다 갔다 하지 않게).
- 앱: 정리된 노트·자동 분류·폴더 나무·서랍 고르기·규칙의 서랍을 모두 새 이름으로 보여 주고, 저장할 때도 새 이름으로 쓴다. 「서랍 이름 바꾸기」는 장부에 적고 그 서랍의 노트를 `update(…, { touch: false })`로 옮긴 뒤 빈 옛 폴더를 휴지통으로 보낸다.
- 정리기: `prepare`가 맨 먼저 옛 이름에 남은 노트를 옮기고(색인·정리 기록에 「이름 바꿈」), batch.md 의 기본 서랍·기존 폴더·규칙은 새 이름으로만 보여 준다. `apply`는 Claude가 옛 이름을 써도 새 이름으로 넣는다.
- 기본 서랍 이름 지킴이: `organizer/taxonomy.json`의 `known`은 한 번이라도 내보낸 이름. 그 이름이 지금 이름으로 이어지지 않으면 `tools/export-taxonomy.mjs`와 `npm test`가 멈추고 `RENAMED`에 적으라고 한다.
- 분류 규칙이 바뀌면 새 노트부터 적용. 이미 정리된 노트는 규칙에 맞는 것을 세어 알림으로 묻고, 누를 때만 옮긴다(`ruleHit`는 자동 분류와 같은 기준).

## 링크 분류와 폰 공유

- 링크는 사이트보다 **내용**이 먼저다. 공유로 온 페이지 제목, 함께 적은 글, 주소 속 낱말로 정하고, 모자라면 사이트로 짐작한다.
  - 주소 속 낱말(`urlWords`): 경로와 검색어를 풀어 한글은 그대로(카페24 상품 주소 `/product/린넨-오버핏-셔츠/123`), 영어는 `URL_WORDS`로 사전 낱말로 바꿔 함께 찾는다(dresses → 원피스, restaurants → 맛집). 인스타 계정 이름도 같다(seoul_foodie → 맛집).
  - 앱이 스스로 적은 문장(「…의 릴스를 저장했어요」「인스타그램에서 보기」, 주소만 적힌 링크 글자, 인스타 릴스 태그)은 분류에 쓰지 않는다.
  - 유튜브·틱톡·블로그 같은 플랫폼은 무엇이든 올라오니 약하게(1점) 친다. 「10분 김치찌개 레시피」 유튜브 → 요리·맛집 › 레시피.
  - 단서가 없으면: `HOST_HINTS`(패션·음식 낱말이 든 사이트 이름, shop/news/map…) → 상품 페이지 꼴(`SHOP_PATH`: /product/, ?product_no=) → 쇼핑. 그래도 모르면 **링크 › 사이트 이름**(`LINK_DRAWER`, weak). 블로그·카페·SNS·짧은 주소·처음 보는 사이트가 여기 온다. 공부·자료로 보내지 않는다.
  - Claude 정리기는 링크 노트를 페이지·캡션 내용으로 나누고 「링크」는 쓰지 않는다(내용을 전혀 못 읽었을 때만 링크/사이트 이름).
- 폰 공유(안드로이드, 설치한 앱): `manifest.webmanifest`의 `share_target`은 POST multipart(제목·글·주소·사진). `sw.js`가 받아서 사진은 캐시 `td-share`에 잠시 두고 `#/share?shared=번호`로, 글·링크만 오면 `?title=&text=&url=`로 앱을 연다. 받기 화면은 사진을 꺼내 사진 노트로 만들고 캐시를 지운다. 안드로이드는 주소를 글 속에 넣어 보내므로 글에서 주소를 꺼내 제목과 함께 링크 노트로 만든다(제목 끝의 「: 네이버 블로그」 등은 뗀다).
- 아이폰은 웹 앱이 공유 목록에 들어갈 수 없어 단축어(`docs/단축어.md`)로 연다(`js/core/shortcut.js`). 마지막 동작은 「웹 페이지 보기」(사파리 탭을 만들지 않는 창)를 권한다. 아이폰·아이패드는 구글 로그인을 작은 창 대신 화면 이동으로 한다(`prefersRedirect`: 사파리는 작은 창을 새 탭으로 열고, 「웹 페이지 보기」 안에서는 작은 창이 안 열림).
  - 링크·글: 권장은 `…/#t=[Base64 → URL 인코딩]`(글 속 `https://`가 그대로 있으면 아이폰이 주소를 둘로 읽어 탭이 두 개 열리고 앱은 빈 내용을 받는다). 예전 꼴 `…/?text=[단축어 입력]`도 받는다. 인코딩하지 않아도 되게 `?text=` 뒤를 통째로 읽는다(공유한 주소 속 & # 도). 단축어가 잘못 만들어졌으면 받기 화면이 고칠 곳을 알려 준다(비어 있음, 변수를 글자로 씀, 사진을 링크 단축어로 보냄).
  - 사진: 단축어가 640px JPEG로 줄여 Base64로 바꾼 뒤 `…/#img=…`로 연다(`#` 뒤라 서버로 가지 않음). 앱은 열리자마자 그 글자를 이 탭의 sessionStorage로 옮기고 주소를 `#/share?img=…`로 바꾼 뒤(구글 열쇠를 다시 받으러 다녀와도 남게) 사진 노트로 만든다. 사파리는 복사된 것을 읽을 때 반드시 누르게 해서 클립보드 대신 이 길을 쓴다. 붙여넣기 방식(`?paste=1`)은 예비로 남긴다.
  - 공유로 넣은 뒤에는 그 노트를 열고 「저장한 이유」 칸으로 가서 한마디 적을 수 있게 한다(분류와 Claude 정리에 쓰임).
  - 받기 화면은 드라이브 전체 목록을 기다리지 않고 바로 저장한다(앱은 `#/share`·`#/paste`면 기기 사본이 없어도 곧바로 화면을 연다). 화면 고르기는 주소를 바꾼 뒤 다시 읽는다(`syncFromLocation`). 안 그러면 사파리가 기기 사본을 지웠을 때 공유 하나에 동기화 시간(노트 수에 비례)이 들었다.
  - `tests/e2e/share.e2e.cjs`: 가짜 구글 드라이브(`fakedrive.cjs`, 폴더·부모·404·늦은 응답)와 가짜 구글 로그인으로 사파리 링크·인스타 릴스·네이버 쇼핑·메모 앱 글·스크린샷·열쇠 만료·첫 로그인·아이폰 크롬을 그대로 재현해, 드라이브의 어느 폴더에 무엇이 저장되는지와 걸린 시간을 본다.
- 링크 노트는 `site`(사이트 이름: 무신사, 네이버 블로그, 모르면 주소)를 머리말에 남긴다. 분류에는 쓰지 않고 찾기와 보이는 이름에 쓴다. 제목이 없으면 「무신사 상품 · 린넨 셔츠」「네이버 블로그 글」「유튜브 영상」처럼 보인다(`linkTitle`).

## 연관 노트와 생각 지도

`js/core/related.js` · `js/ui/related.js` · `js/ui/views/graph.js`

- 분류 다음 단계로, 서로 이어 볼 만한 노트를 기기 안에서 고른다(서버·AI 요청 없음, 라이브러리가 바뀔 때만 다시 계산).
- 점수 = 낱말 0.75 × TF-IDF 코사인(제목 3배, 요약 2배, 본문 1배. 주소·사진 표시·「사진 속 글자」 제목은 뺌) + 같은 태그 하나에 0.18(두 개까지, 직접 단 태그와 자동 태그를 함께) + 같은 사이트 0.15(인스타·유튜브·블로그 플랫폼처럼 흔한 곳은 0.03) + 같은 소분류 0.2(같은 세부 서랍 0.14, 같은 서랍만 0.07. 단서 없이 메모에 둔 노트는 서랍 점수 없음).
- 서랍이 같다는 것만으로는 잇지 않는다: 낱말(코사인 0.08 이상)·태그·사이트 중 하나는 겹쳐야 한다. 그래서 「들기름 막국수」와 「토마토 달걀볶음」은 둘 다 레시피라도 겹치는 게 없으면 잇지 않고, 생각 지도의 같은 동그라미 안에만 모인다.
- 후보는 같은 낱말·태그·사이트를 가진 노트만 계산한다(노트가 많으면 너무 흔한 낱말은 후보를 만들지 않음).
- 생각 지도: 노트마다 가까운 3개를 0.2점 이상이면 점선(추천 연결)으로, 직접 이은 것은 실선. 같은 서랍끼리는 덜 밀고 가운데로 당겨 옅은 동그라미로 모이며, 색은 다른 화면의 서랍 점과 같다. 점에 올리면 오른쪽 아래에 이어진 노트와 이유. 위의 「추천 연결」 단추로 점선을 끄고 켠다(이 기기에 기억).
- 노트 오른쪽 「비슷한 노트」: 같은 계산으로 다섯 개와 이유, 「잇기」를 누르면 양쪽 노트에 실제 연결을 쓴다(그 뒤로는 실선).

## 필터

`js/core/filter.js` · `js/ui/parts/filters.js`

- 모든 노트·서랍·태그·즐겨찾기·찾기 화면 위의 막대: 날짜 · 종류 · 서랍(› 세부 서랍) · 태그(여러 개, 모두 가진 노트) · 사이트 · 조건, 그리고 보기 메뉴의 정렬(최근 넣은 순, 오래된 순, 최근 고친 순, 이름 순).
- 날짜: 오늘, 어제, 이번 주(월요일부터), 최근 7일, 이번 달, 최근 30일, 올해, 기간 지정. 기준은 넣은 날 또는 고친 날. 날짜가 없으면 노트 번호(만든 시각)로.
- 조건: 할 일 있음, 남은 할 일, 할 일 다 함, 사진 있음, 요약 있음, 즐겨찾기, 직접 정한 서랍, 자동 분류만, 태그 없음. 할 일 조건을 고르면 본문을 아직 안 받은 노트를 받아 온다.
- 고른 값은 주소(`#/all?d=week&dr=쇼핑/가전&tag=세일`)에 담긴다. 뒤로 가기에는 쌓지 않는다.

## / 명령어와 함께 쓰는 설정

`js/core/slash.js` · `js/ui/parts/slash.js` · `js/core/settings.js`

- 입력칸(첫 화면, 가운데 입력창)에서 줄 처음이나 띄어쓰기 뒤의 `/` → 명령어와 내 키워드(+ 이름이 맞는 서랍), `#` → 쓰던 태그(없으면 새 태그), `@` → 서랍(기본·세부·이미 있는 폴더, 없으면 새 서랍). ↑↓, Enter·Tab, Esc. 주소 안의 `/`·`#`, 이메일의 `@`는 걸리지 않는다.
- 기본 명령어: 할일, 오늘, 내일, 어제, 지금, 태그, 서랍, 사진, 붙여넣기, 크게. 노트 편집기의 `/` 메뉴는 블록(제목, 목록, 할 일, 인용, 코드, 구분선, 사진, 잇기) + 날짜·시각 + 내 키워드.
- 넣을 때 `#태그`는 태그로, 아는 서랍의 `@서랍`은 그 폴더로(직접 정한 서랍) 보내고 글에서는 뺀다. 아이폰 공유·사진 메모에도 같다. 모르는 `@이름`(인스타 계정 등)은 그대로 둔다.
- 내 키워드·분류 규칙·자동 분류 설정은 드라이브 `메모/_시스템/settings.json`에 저장해 기기 사이에 함께 쓴다. 밝기, 글꼴, 옆 메뉴, 서랍이 말풍선, 넣고 바로 열기, 첫 줄 제목은 이 기기에만(브라우저 저장).

## 일부러 뺀 것

- 유튜브 정리, 영상 내용(음성·장면) 분석: 사용량이 많이 든다.
- 인스타 아이디·비밀번호 자동 로그인: 약관 위반, 계정 정지 위험. 대신 인스타 공식 "내 정보 다운로드" 파일을 쓴다.
- 앱 안에서 바로 AI 답변: 구독을 웹앱에서 직접 쓸 수 없다. 대신 관련 노트를 붙여 Claude 앱으로 넘긴다.
